## RabbitMQ 개요

![rabbit_logo.png](images/rabbit_logo.png)

RabbitMQ는 얼랭으로 만들어진 메시지 전송 브로커 오픈소스이다.  
시스템 간 비동기 메시징을 가능하게하여 서비스 간 통신을 안정적이고 효율적으로 처리할 수 있게 해준다.  
플랫폼 독립적이며, 가볍고 다양한 언어들의 클라이언트 라이브러리를 제공하고, 유연한 성능과 안정성을 제공한다.  
클러스터를 설정할 때 큐를 HA(High Available) 로 설정하여 여러 노드에 복제할 수 있으며 이를 통해 장애 상황에서도 메시지 손실을 최소화할 수 있다.  
또한 플러그인 구조를 통해 기능 확장이 용이하며, Federation 플러그인을 활용하면 데이터 동기화와  분산된 메시징 구성이 가능하다.  
최근 MSA 환경에서 널리 쓰이는 기술중에 하나이며, 대량의 데이터 전송 시 발생할 수 있는 과부하를 분산시키며, 
비동기 처리 및 지연이 필요한 작업을 효과적으로 관리 해줄 수 있다.

### 필요성
이러한 메시지 큐는 왜 필요할까?
우리가 주문 시스템을 만든다고 가정해보자.

사용자는 상품 주문 버튼을 통해 주문을 완료하려고 할 것이다.
하지만 서버 관점에서는 주문 처리 과정에 여러 단계의 복잡한 작업이 포함될 수 있다.

이때 사용자에게는 주문이 정상적으로 접수되었다는 사실만 먼저 빠르게 알려주는 것이 사용자 경험 측면에서 더 좋다.
우리가 카페에서 주문할 때를 떠올려보면, 주문이 접수되면 바로 진동벨을 받지
커피가 완성된 후에야 주문이 접수되었다고 알려주지는 않는다.

시스템도 마찬가지다. 사용자에게는 먼저 요청이 정상적으로 접수되었음을 알리고,
복잡한 처리는 백그라운드에서 비동기로 수행하면 된다.

이러한 요구사항을 해결하기 위해 비동기 처리 방식이 등장했고,
이를 더 효율적으로 처리하며 MSA 환경에서도 유연하게 활용하기 위해 Kafka, Redis Pub/Sub, RabbitMQ와 같은
플랫폼 독립적인 메시징 큐 오픈소스들이 널리 사용되고 있다
