RabbitMQ Visual Study

Chapter 1

메시지는 큐로 바로 가지 않는다

RabbitMQ는 서비스 사이에 메시지를 맡아두는 브로커다. Producer는 메시지를 발행하고, Exchange는 규칙에 맞는 Queue를 고르며, Consumer는 Queue에서 메시지를 가져가 처리한다.

핵심 메모

주문 시스템에서 사용자는 주문 접수만 빠르게 확인하면 된다. 오래 걸리는 결제, 재고, 알림 처리는 뒤에서 비동기로 처리하면 사용자 경험과 시스템 안정성이 같이 좋아진다.

  • AMQP는 서로 다른 언어와 플랫폼이 같은 방식으로 메시지를 교환하게 해주는 표준 프로토콜이다.
  • Exchange는 메시지를 어느 Queue로 보낼지 결정하는 라우터다.
  • Queue는 Consumer가 가져가기 전까지 메시지를 저장한다.
  • Binding은 Exchange와 Queue 사이의 라우팅 규칙이다.

    Chapter 2

    Work Queue는 일을 나눠서 처리한다

    여러 Consumer가 같은 Queue를 바라보면 메시지는 한 Consumer에게만 전달된다. ready는 아직 안 간 메시지, unacked는 전달됐지만 ACK가 돌아오지 않은 메시지다.

    핵심 메모

    기본 분배는 Round-Robin이다. 작업 시간이 비슷하면 단순하고 좋지만, 긴 작업과 짧은 작업이 섞이면 한 Consumer에게 일이 몰린 것처럼 보일 수 있다.

    • AUTO ACK는 리스너가 정상 종료되면 자동으로 ACK를 보낸다.
    • MANUAL ACK는 처리 완료 시점에 직접 ACK를 보낸다.
    • prefetchCount를 제한하면 먼저 끝난 Consumer가 다음 작업을 받기 쉬워진다.
    • purge는 보통 ready 메시지를 비우며, unacked는 연결 상태에 따라 다르게 보인다.

      Chapter 3

      Exchange가 Queue를 고르고, 실패는 DLQ로 흐른다

      Producer는 Queue 이름을 몰라도 된다. Exchange 이름과 Routing Key로 발행하면 Exchange와 Binding이 실제 Queue를 결정한다. 처리 실패 시 requeue=false이면 DLX를 통해 DLQ로 이동한다.

      핵심 메모

      Direct는 정확히 일치하는 키, Topic은 패턴, Fanout은 전체 브로드캐스트다. RabbitMQ의 DLQ 이동은 consumer의 nack/reject와 requeue=false 결정에 직접 영향을 받는다.

      • Direct는 routing key와 binding key가 정확히 같을 때 전달한다.
      • Topic은 * 한 단어, # 여러 단어 패턴으로 전달한다.
      • Fanout은 routing key를 보지 않고 연결된 모든 Queue로 전달한다.
      • DLX는 실패 메시지를 DLQ로 보내는 Exchange다.
